Quickstart

One endpoint, JSON in, JSON out. Every field is optional: with an empty body you get the best all-round models for a generic request.

POST/v1/rank

Authenticate with Authorization: Bearer <key>: the public beta key, or a workspace key from Settings → API keys (counts against your plan's API quota). Self-hosted instances need no key from the local machine.


      
Request

      

        
FieldTypeMeaning

        
promptstringA single prompt (up to 400k characters).

        
messagesarrayA whole conversation in OpenAI chat format (role + content, text or content parts). Images in content parts imply vision; tool messages or tool_calls imply tool use.

        
taskstringA plain description of the job, e.g. "nightly summarisation of support tickets". Weighted more than prompt text when classifying.

        
toolsarrayTool definitions you will send. Any tools means only tool-capable models are ranked.

        
response_formatobjectStructured-output request; nudges triage toward extraction tasks.

        
weightsobjectHow much each factor matters, any scale: performance, savings, latency, reliability, context, recency. Dimension names (coding, agentic, reasoning, chat) may be used directly and add up to performance with that mix. Aliases: quality, cost, speed, uptime. Omit for automatic weights.

        
performanceobjectExplicit performance mix, e.g. {"coding": 0.7, "reasoning": 0.3}. Omit to use the triage's mix.

        
limitsobjectmax_cost_per_request (USD), max_blended_cost, max_input_cost, max_output_cost ($ per million tokens).

        
filtersobjectHard filters: see Filters.

        
input_tokens, expected_output_tokensintegerOverride the token estimate used for request cost (defaults: measured from your text, and a triage-based output estimate).

        
current_modelstringThe model the conversation is on now. Turns on cache-aware costing and the switching recommendation (see caching).

        
cacheobjectseconds_since_last_request (cache warmth), expected_turns (cost horizon, default 5 for conversations), cached_tokens (if you know it), tokens_per_turn, ttl_seconds (override the provider default), provider (where the cache lives).

        
min_switch_gainnumberScore points an alternative must gain over the current model before switching is recommended (default 2).

        
limitintegerResults to return, 1–50 (default 10).

        
dedupebooleanOne row per model when it is sold several ways, e.g. paid and :free (default true).

        
explainbooleanInclude human-readable reasons per result (default true).

      


      
Weights & scoring

      
Each candidate is scored 0–100 on every factor; the final score is the weighted mean, and contributions shows each factor's share of it.

      
FactorHow it is measured

      
Automatic weights. Without weights, Modelfit uses the triage: performance 0.55, savings 0.30, latency 0.10, reliability 0.05 for medium complexity; 0.70 / 0.17 / 0.06 / 0.07 for high; 0.45 / 0.35 / 0.15 / 0.05 for low, with extra reliability for agentic and tool-using work. Auto mode also applies a quality floor: models below 60% (low complexity), 75% (medium) or 85% (high) of the best candidate's performance are left out, so nothing near-useless wins on price alone. Set filters.min_performance to control this yourself.

      
Performance uses the same 0–100 category scores as the leaderboard, built from two dozen benchmarks (Artificial Analysis, Epoch AI, LMArena). A model needs scores covering at least half of your mix to be ranked on performance; performance.coverage says how much it had.

      
Latency is measured endpoint data where the source publishes it; otherwise an estimate from model size signals (parameter count, tier names like mini or pro), output price and reasoning support. latency.basis says which. Treat estimated latency as a coarse ranking signal, not a benchmark.


      
Triage (NLP)

      
Every request is classified before ranking; the result comes back in triage and drives the automatic performance mix, weights, token estimates and implied requirements.

      
    
        
  • Classifier: multinomial naive Bayes over word unigrams and bigrams (stop words removed, light stemming), trained on a labelled seed corpus of typical requests.
    • 
        
  • Structural signals on top: code blocks and syntax, stack traces, SQL, LaTeX/equations, tool definitions and tool calls, translation and summarisation requests, structured-output keywords, plus a few non-English cues.
    • 
        
  • Source weighting: the task description counts double, the latest user turn more than earlier turns and the system prompt.
    • 
        
  • Also returned: complexity (low / medium / high), language, estimated input tokens, suggested output tokens, and needs (tools, vision, long context, structured output).
    •

Conversations & caching

      
Mid-conversation, the cheapest model is often the one you are already on. Providers cache the prompt prefix of recent requests and bill it at a fraction of the input price (typically 10%), but only on the model and provider that served it. Moving a long conversation to another model means paying full price for the whole history once, plus a cache-write premium where the provider charges one (for example 1.25×), before caching pays off there.

      
Send the conversation in messages and the model it runs on in current_model, and Modelfit prices every candidate over the next cache.expected_turns turns:

      
    
        
  • Current model, warm cache: the earlier messages are billed at its cached-read price. The cache counts as warm while seconds_since_last_request is under the provider's TTL (5 minutes for most; configurable).
    • 
        
  • Every other model: the first turn pays the full input price plus any write premium; later turns read from the new cache.
    • 
        
  • Per provider endpoint: cached-read and cache-write prices and long-context price tiers come from each endpoint's published pricing. Models without cache pricing pay full input every turn.
    • 
        
  • The savings factor uses this horizon cost, so the ranking itself is cache-aware.
    • 
      

      
The response adds a switching block:

      
switching
{ "current_model": "deepseek/deepseek-v4.1-flash-1017", "recommendation": "stay",
  "best_alternative": "deepseek/deepseek-v4.1-flash", "score_gain": -2.34, "min_switch_gain": 2,
  "stay_horizon_usd": 0.0028, "switch_horizon_usd": 0.0030, "switch_now_extra_usd": 0.0011, "breakeven_turn": 11,
  "cache": { "warm": true, "cached_tokens": 24033, "ttl_seconds": 3600, "expires_in_seconds": 3570 },
  "cheaper_equivalent": null,
  "reason": "The best alternative scores only -2.3 … Switching to it breaks even on cost at turn 11. Your cache is warm …" }

      

        
FieldMeaning

        
recommendationswitch when the best alternative beats the current model by at least min_switch_gain score points with cache costs priced in (or the current model fails a filter/limit); otherwise stay.

        
switch_now_extra_usdWhat switching costs on this turn compared with staying: mostly the cache you would give up.

        
stay_horizon_usd, switch_horizon_usd, breakeven_turnCumulative cost over the horizon each way, and the turn at which switching becomes cheaper (simulated up to 50 turns).

        
cheaper_equivalentThe model with performance within 2 points of yours that saves the most over the horizon, judged on cost alone.

        
cacheWhether your current model caches, whether the cache is still warm, and seconds until it expires: a good moment to switch is right after it expires.

      

      
Each result also carries cost.horizon_usd, cache.warm, cache.cached_tokens and cache.saved_this_turn_usd. Token counts are one estimate for every model; real tokenizers differ by about ±15%.


      
Filters & limits

      

        
FilterMeaning

        
countries / exclude_countriesISO country codes of the model developer's headquarters, e.g. ["US", "FR"]. Models with an unknown developer country (community fine-tunes) are excluded by countries unless include_unknown_country is true.

        
open_weightstrue: only models with published weights; false: only closed models.

        
vendors / exclude_vendorsDeveloper ids as in model ids, e.g. openai, anthropic, mistralai.

        
models / exclude_modelsAllow- or deny-list of model ids.

        
tools, reasoning, visionRequire (true) or exclude (false, for reasoning) the capability. Tools and vision are implied by the request when it contains tools or images.

        
min_contextMinimum context window in tokens. Implied when your request plus expected output exceed 8k tokens.

        
freetrue: only $0 models; false: exclude them.

        
max_age_daysOnly models released within this many days.

        
min_performance, min_reliability, min_benchmark_coverageFloors on the performance score, reliability score (0–100) and benchmark coverage (0–1).

      

      
The response's excluded object counts how many models each filter or limit removed, so an empty result explains itself.


      
Response

      
200 OK (abridged)

      

        
FieldMeaning

        
results[]Ranked models: score, per-factor factors and contributions, performance (score, coverage, dimension scores), cost (estimated request USD, $/M in/out, cheapest channel and provider), latency, reliability, country, open weights, capabilities, explanation.

        
triageThe classification of your request (see above).

        
weights, performance_mix, basisThe normalised weights and mix actually used, and whether they came from your request or the triage.

        
switchingWith current_model: stay or switch, with horizon costs, break-even turn and cache state (see caching).

        
assumptionsToken counts used for cost (conversation prefix, new tokens, horizon), cache TTL and warmth, implied requirements, auto quality floor.

        
candidates, excludedHow many models were ranked, and why the rest were not.

        
generated_atWhen the underlying price and benchmark snapshot was built (refreshed every 30 min to 24 h per source).

      


      
Other endpoints

Same body as /v1/rank; returns only the classification.

      
GET/v1/rank/options
Factors, dimensions, task types, and the countries and vendors present in today's data with model counts: handy for building forms.
